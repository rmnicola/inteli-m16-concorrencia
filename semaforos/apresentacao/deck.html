Um contador de recursos

semáforo s

esperando

A abstração antes da API. Um semáforo é um número inteiro que conta unidades livres de um recurso: vagas num estacionamento, conexões com um banco, posições num buffer. Avance: cada thread que quer usar o recurso pega uma unidade (uma ficha), e o valor cai. Quando o valor chega a zero, o recurso se esgotou: quem chega espera. Quando alguém devolve uma unidade e há gente esperando, a unidade vai direto para uma delas; se não há ninguém, o valor sobe. Dois atos só: pegar (esperando se preciso) e devolver (acordando alguém se preciso). É isso que sem_wait e sem_post fazem, no próximo slide. Pergunta para a turma: e se o valor inicial for 1? (um lock). E se for 0? (ninguém passa até alguém devolver: ordem).

sem_wait e sem_post

#include <semaphore.h>
sem_t s;
sem_init(&s, 0, 1);int sem_wait(sem_t *s) {
    decrement the value of semaphore s by one
    wait if value of semaphore s is negative
}int sem_post(sem_t *s) {
    increment the value of semaphore s by one
    if there are one or more threads waiting, wake one
}

Declarar e dar o valor inicial: aqui, 1.

Pegar: decrementa e, se ficou negativo, dorme.

Devolver: incrementa e acorda uma que espera. Nunca espera.

Negativo, o valor é quantas threads esperam.

O valor inicial decide o comportamento.

Seção 31.1, figs. 31.1 e 31.2. Bloco 1: sem_init(&s, 0, 1) cria o semáforo com valor 1; o 0 do meio diz que ele é compartilhado entre threads do mesmo processo (outro valor serve para sincronizar processos; ver a man page). Bloco 2: sem_wait decrementa e, se o valor ficou negativo, dorme; senão, retorna na hora. Várias threads podem estar dormindo no mesmo semáforo. Bloco 3: sem_post incrementa e, se há alguém esperando, acorda um; não espera condição nenhuma. Avance: com esta definição (a de Dijkstra), o valor negativo é o número de threads esperando. Avance: antes de usar, sempre o valor inicial, que decide o comportamento: é a pergunta que vai voltar em todos os exemplos. Por enquanto, as duas operações são atômicas; como garantir isso é o próximo slide. Nota histórica: Dijkstra chamou sem_wait de P() e sem_post de V(), de palavras holandesas (proberen/verhogen, depois prolaag/verhoog).

Por dentro: lock e variável de condição

typedef struct __Zem_t {
    int value;
    pthread_cond_t cond;
    pthread_mutex_t lock;
} Zem_t;// only one thread can call this
void Zem_init(Zem_t *s, int value) {
    s->value = value;
    Cond_init(&s->cond);
    Mutex_init(&s->lock);
}
void Zem_wait(Zem_t *s) {
    Mutex_lock(&s->lock);
    while (s->value <= 0)
        Cond_wait(&s->cond, &s->lock);
    s->value--;
    Mutex_unlock(&s->lock);
}void Zem_post(Zem_t *s) {
    Mutex_lock(&s->lock);
    s->value++;
    Cond_signal(&s->cond);
    Mutex_unlock(&s->lock);
}

As três peças de sempre: estado, variável de condição e lock.

O valor inicial vira o estado.

wait: dorme enquanto não há unidade livre; depois pega uma.

post: devolve uma e acorda alguém.

Aqui o valor nunca fica negativo: só se decrementa depois da espera.

Seção 31.8, fig. 31.17: o "Zemaphore", um semáforo construído com um lock e uma variável de condição. Mostrar logo de cara para tirar a mágica: é exatamente o padrão do capítulo anterior. Bloco 1: estado (value), CV e lock juntos. Bloco 2: o valor inicial. Bloco 3: Zem_wait pega o lock e dorme na CV enquanto value <= 0 (while, por causa da semântica Mesa); quando passa, decrementa. Bloco 4: Zem_post incrementa e sinaliza. Avance: uma diferença sutil para o semáforo de Dijkstra: aqui o valor nunca fica abaixo de zero, porque só se decrementa depois de esperar; não vale o invariante "negativo = número de threads esperando". É mais fácil de implementar e é como o Linux faz. O contrário (construir variáveis de condição com semáforos) é bem mais difícil: gente experiente tentou no Windows e acumulou bugs.

Qual deve ser o valor inicial X?

X = 1: uma unidade, uma thread por vez.

T0 faz wait: 1 → 0, e entra.

T1 faz wait: 0 → −1, e dorme.

T0 sai com post: −1 → 0, e acorda T1.

T1 sai com post: 0 → 1.

Seção 31.2, figs. 31.3 a 31.5. O primeiro uso: semáforo como lock. Bloco 1: o semáforo m, com valor inicial X. Bloco 2: sem_wait e sem_post em volta da seção crítica. Avance: qual deve ser X? Deixe a turma responder antes. Avance: 1. Avance: T0 chama sem_wait, o valor vai a 0; como não é negativo, retorna e T0 entra. Avance: T1 tenta entrar enquanto T0 está dentro: o valor vai a −1, e T1 dorme. Avance: T0 sai com sem_post: o valor volta a 0 e T1 acorda. Avance: T1 roda a seção crítica e sai: o valor volta a 1. Como só há dois estados (preso, livre), o lock feito com semáforo se chama semáforo binário.

Semáforo para ordenação

sem_t s;void *child(void *arg) {
    printf("child\n");
    sem_post(&s); // signal here: child is done
    return NULL;
}int main(int argc, char *argv[]) {
    sem_init(&s, 0, X); // what should X be?
    printf("parent: begin\n");
    pthread_t c;
    Pthread_create(&c, NULL, child, NULL);
    sem_wait(&s); // wait here for child
    printf("parent: end\n");
    return 0;
}

O filho avisa que terminou.

O pai espera o aviso.

Qual deve ser X? Zero.

Pai primeiro: 0 → −1, e dorme até o post do filho.

Filho primeiro: 0 → 1. O wait do pai leva a 0 e não dorme.

Sem done: o valor do semáforo guarda o aviso.

Seção 31.3, figs. 31.6 a 31.8. O pai espera o filho, o mesmo join da fig. 30.3, agora com um semáforo. Bloco 1: o semáforo. Bloco 2: o filho imprime e faz sem_post. Bloco 3: o pai cria o filho e faz sem_wait. Avance: qual o valor inicial? Deixe a turma pensar. É 0: o pai só deve passar depois de um post. Avance: caso 1, o pai chega primeiro ao wait: o valor vai a −1 e ele dorme; quando o filho roda, o post leva a 0 e acorda o pai. Avance: caso 2, o filho roda até o fim antes: o post leva a 1 e não acorda ninguém; quando o pai chega, o wait leva a 0 e ele segue sem dormir. Avance: compare com a variável de condição: lá precisávamos da variável done, porque a CV não guarda o sinal. O semáforo guarda: o valor é o estado. Uso típico: uma thread espera algo acontecer e outra faz acontecer e avisa.

Produtor/consumidor, com semáforos

int buffer[MAX];
int fill = 0;
int use = 0;void put(int value) {
    buffer[fill] = value;    // Line F1
    fill = (fill + 1) % MAX; // Line F2
}int get() {
    int tmp = buffer[use];   // Line G1
    use = (use + 1) % MAX;   // Line G2
    return tmp;
}
sem_t empty;
sem_t full;

sem_init(&empty, 0, MAX); // MAX are empty
sem_init(&full, 0, 0);    // 0 are full

O buffer circular de MAX posições, sem count.

Quem conta agora são dois semáforos: posições livres e ocupadas.

Seção 31.4, figs. 31.9 e 31.10. De volta ao buffer limitado. O buffer é o mesmo da fig. 30.13, mas sem count: put grava em buffer[fill] e avança fill (linhas F1 e F2); get lê buffer[use] e avança use (G1 e G2). Avance: dois semáforos fazem a contagem. empty começa com MAX (todas as posições livres); full começa com 0 (nenhuma ocupada). É a abstração do começo: o produtor pega uma vaga livre (wait em empty) e devolve uma ocupada (post em full); o consumidor, o contrário.

Esperar vagas e dados

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        sem_wait(&empty);       // Line P1
        put(i);                 // Line P2
        sem_post(&full);        // Line P3
    }
}
void *consumer(void *arg) {
    int tmp = 0;
    while (tmp != -1) {
        sem_wait(&full);        // Line C1
        tmp = get();            // Line C2
        sem_post(&empty);       // Line C3
        printf("%d\n", tmp);
    }
}

O produtor pega uma vaga, põe o item e avisa que há um dado.

O consumidor pega um dado, tira o item e devolve a vaga.

Com MAX = 1, um produtor e um consumidor: funciona.

E com MAX = 10 e dois produtores?

Fig. 31.10. Bloco 1: o produtor espera uma posição livre (P1), põe (P2) e avisa que há uma posição ocupada (P3). Bloco 2: o consumidor espera uma posição ocupada (C1), tira (C2) e devolve uma livre (C3). Avance: MAX = 1, um produtor e um consumidor, consumidor primeiro: ele faz wait em full (0 → −1) e dorme. O produtor faz wait em empty (1 → 0), põe e faz post em full (−1 → 0), acordando o consumidor. Se o produtor continuar, para em empty (0 → −1); se o consumidor rodar, consome. Funciona, e funciona com mais threads. Avance: e com MAX = 10 e vários produtores? Olhe put() de novo.

Dois produtores, um dado perdido

Fig. 31.10 com MAX = 10 e dois produtores, Pa e Pb. Os dois já passaram do sem_wait(&empty): há vagas de sobra, então nada os segura. Avance: Pa começa o put: grava A em buffer[0] (F1). Avance: Pa é interrompida antes de avançar fill (F2); Pb roda e grava B em buffer[fill], que ainda é 0: A foi sobrescrito. Avance: Pb avança fill para 1. Avance: Pa volta e avança fill de novo, para 2. Resultado: o dado A se perdeu e buffer[1] nunca foi escrito; o consumidor vai ler lixo. Encher o buffer e avançar o índice é uma seção crítica: faltou exclusão mútua.

Cada um espera o outro

deadlock

O deadlock da fig. 31.11, com um produtor e um consumidor (MAX = 1). Avance: o consumidor roda primeiro e pega o mutex (C0): 1 → 0. Avance: não há dado; o wait em full (C1) leva full a −1 e o consumidor dorme, mas continua segurando o mutex. Avance: o produtor roda; ele tem um dado e poderia acordar o consumidor, mas a primeira coisa que faz é pedir o mutex (P0). Avance: o mutex está com o consumidor: 0 → −1, e o produtor dorme. O consumidor espera o produtor sinalizar full, e o produtor espera o consumidor soltar o mutex: um ciclo, deadlock clássico.

O mutex só em volta de put e get

void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        sem_wait(&empty);  // Line P1
        sem_wait(&mutex);  // Line P1.5 (lock)
        put(i);            // Line P2
        sem_post(&mutex);  // Line P2.5 (unlock)
        sem_post(&full);   // Line P3
    }
}
void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        sem_wait(&full);   // Line C1
        sem_wait(&mutex);  // Line C1.5 (lock)
        int tmp = get();   // Line C2
        sem_post(&mutex);  // Line C2.5 (unlock)
        sem_post(&empty);  // Line C3
        printf("%d\n", tmp);
    }
}

Reduzir o escopo do lock: a espera por vaga ou dado fica de fora.

O buffer limitado com semáforos: um padrão para levar.

Fig. 31.12, a solução que funciona. Avance: a correção é reduzir o escopo do lock: o mutex fica só em volta de put e get (a seção crítica de verdade), e as esperas em empty e full ficam de fora. Ninguém dorme segurando o mutex. Avance: é o buffer limitado, um padrão comum em programas com threads; entenda agora, use depois. Em código modular, o mutex ficaria dentro de put() e get().

Leitores e escritores

typedef struct _rwlock_t {
  sem_t lock;      // binary semaphore (basic lock)
  sem_t writelock; // allow ONE writer/MANY readers
  int   readers;   // #readers in critical section
} rwlock_t;void rwlock_init(rwlock_t *rw) {
  rw->readers = 0;
  sem_init(&rw->lock, 0, 1);
  sem_init(&rw->writelock, 0, 1);
}void rwlock_acquire_readlock(rwlock_t *rw) {
  sem_wait(&rw->lock);
  rw->readers++;
  if (rw->readers == 1) // first reader gets writelock
    sem_wait(&rw->writelock);
  sem_post(&rw->lock);
}
void rwlock_release_readlock(rwlock_t *rw) {
  sem_wait(&rw->lock);
  rw->readers--;
  if (rw->readers == 0) // last reader lets it go
    sem_post(&rw->writelock);
  sem_post(&rw->lock);
}void rwlock_acquire_writelock(rwlock_t *rw) {
  sem_wait(&rw->writelock);
}

void rwlock_release_writelock(rwlock_t *rw) {
  sem_post(&rw->writelock);
}

Um lock, um writelock e quantos leem agora.

Os dois semáforos começam em 1.

Entrar para ler: conta mais um leitor.

Sair de ler: conta menos um.

Escrever: só o writelock.

O primeiro leitor tranca os escritores; o último destranca.

Seção 31.5, fig. 31.13. Exemplo: uma lista com inserções (que mudam a estrutura) e buscas (que só leem). Várias buscas podem rodar juntas, desde que nenhuma inserção esteja em andamento. Bloco 1: lock (semáforo binário que protege readers), writelock (um escritor ou muitos leitores) e readers. Bloco 2: os dois semáforos começam em 1. Bloco 3: para ler, pega lock, incrementa readers e solta. Bloco 4: para sair, decrementa. Bloco 5: o escritor só usa o writelock, como um lock comum. Avance: o pulo do gato: o primeiro leitor a entrar também faz wait no writelock, e o último a sair faz post. Enquanto houver um leitor dentro, nenhum escritor entra; mais leitores entram à vontade.

O escritor pode passar fome

O lock de leitores e escritores em ação. Avance: R1 é o primeiro leitor: readers vai a 1 e ele faz wait no writelock (1 → 0). Avance: R2 entra junto: readers 2, sem tocar no writelock. Avance: W quer escrever: wait no writelock (0 → −1), e dorme. Avance: R3 chega depois de W e entra na frente, porque ainda há leitores dentro. Com leitores chegando sem parar, W nunca entra: os leitores podem matar o escritor de fome. Avance: R1 e R2 saem. Avance: R3, o último leitor, faz post no writelock (−1 → 0) e acorda W, que enfim escreve. Há soluções mais sofisticadas (impedir novos leitores quando um escritor espera), mas custam: locks de leitores e escritores têm mais overhead e muitas vezes não ganham de um lock simples. Quadro "Hill's Law": simples e burro pode ser melhor; tente primeiro o simples.

Centenas de threads, memória para poucas.

wait e post em volta da região pesada.

Valor inicial N: no máximo N threads lá dentro, como as fichas do começo.

throttling

Seção 31.7, thread throttling. Centenas de threads trabalham em paralelo, mas numa parte do código cada uma aloca muita memória. Se todas entram nessa região ao mesmo tempo, a soma passa da memória física, a máquina começa a fazer swap (thrashing) e tudo fica lento. Avance: um semáforo resolve: wait antes da região, post depois. Avance: com valor inicial N, no máximo N threads ficam lá dentro ao mesmo tempo: é a animação do começo, com N fichas. É uma forma de controle de admissão (admission control). Fecho: um semáforo serve de lock (valor 1), de ordem (valor 0) e de contador de recursos (valor N).
